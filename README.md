# Unicode Spoof Guard External Library

## Solution Workflow

1. **Embedded Data & Configuration**
   - Unicode resources (including the baseline `src/confusables.txt`) and policy/configuration files are embedded in the assembly (`data/`, `config/`).
   - Loader classes under `src/Data/` deserialize the resources and cache them for runtime use. The confusables dataset is memory-mapped from `confusables.bin` for fast startup, and can be replaced at runtime via the `RefreshConfusablesData` server action.

2. **Detection Pipeline**
   - `ConfusablesParser` builds an index of single- and multi-character confusables, including ASCII homoglyph tables.
   - `ThreatIndicatorStore` loads blocklists generated by the feed manager.
   - `SpoofDetector` executes the ordered pipeline:
     1. Homoglyph detection
     2. Mixed-script checks against policy allowances
     3. Invisible/format character detection
     4. Bidirectional control detection
     5. Threat intelligence lookups (optional per call)
   - `Canonicalizer` provides normalized text using the same index, ensuring consistent comparisons.

3. **Public API & OutSystems Mapping**
   - `Analyzer` merges default `SpoofGuardOptions` with per-call `AnalysisContext` derived from `AnalysisOptions`.
   - `UnicodeSpoofGuard` surfaces analyzer methods as server actions.
   - `IUnicodeSpoofGuard` defines the OutSystems contract using `OSInterface`/`OSAction` annotations so the platform publishes the actions automatically when the library is imported.

4. **Operational Tooling**
   - `tools/UpdateConfusables` refreshes Unicode data (see instructions below).
   - `src/Cli/` exposes the `sync-feeds` command to ingest threat intelligence.
   - `tools/ProfileStartup` measures cold-start performance for regression tracking.

## Refreshing the Unicode Confusables Dataset
When the Unicode Consortium publishes a new `confusables.txt`, update the embedded data with the tooling bundled in this repo:

1. **Run the updater.** From the repository root execute:<br/>
   ```powershell
   dotnet run --project tools/UpdateConfusables -- -v
   ```  
   - Use `--check` to validate freshness without writing files.  
   - Use `--local path\to\confusables.txt` to regenerate from a downloaded file.  
   - The tool regenerates `data/confusables.json` (and the memory-mapped `confusables.bin` cache) with metadata, hash validation, and parsed entries.
2. **Review the diff.** Inspect the changes under `data/` to confirm the new version/date and mapping adjustments.
3. **Run the tests.** Ensure `dotnet test` still passes so downstream behaviour remains stable.
4. **Commit & document.** Commit the updated dataset and note any behavioural impact in release notes/changelog.  

> GitHub Actions runs `.github/workflows/confusables-staleness.yml` weekly and on PRs, calling the updater in `--check` mode to alert you when the bundled version falls behind Unicode.

## Detection Pipeline Summary

| Stage | Purpose | Configurability |
| --- | --- | --- |
| Homoglyph scan | Flags characters or multi-character sequences that mimic others | Strict mode toggles ASCII/identical suppression |
| Mixed-script analysis | Detects unexpected script combinations, cross-checks policy profiles | Locale/Policy overrides via `AnalysisOptions` |
| Invisible character scan | Highlights zero-width, control, or other non-visible characters | Always on |
| Bidirectional control scan | Detects Bidi overrides that alter visual ordering | Always on |
| Threat intelligence match | Compares canonical tokens to synced blocklists | Enable/disable per call; feeds pluggable |

## Operational Workflow

1. **Refresh Unicode data** – Prefer the OutSystems server action `RefreshConfusablesData` (defaults to the official Unicode URL) to update mappings at runtime. For repository updates, run `dotnet run --project tools/UpdateConfusables -- -v`, review diffs, execute tests, and commit (see “Refreshing the Unicode Confusables Dataset”).
2. **Sync threat feeds** – Optionally run `dotnet run --project src/Cli/UnicodeSpoofGuard.Cli -- sync-feeds` (with `--dry-run` for inspection) to refresh `data/threat_indicators.json`.
3. **Package for OutSystems** – Execute:
   ```powershell
   cd src
   ./generate_upload_package.ps1
   ```
   The script produces `.out/ExternalLibrary.zip` ready for upload.
4. **Import into ODC** – Upload the package, add the dependency in ODC Studio, and consume the server actions with optional `AnalysisOptions` to tune behaviour.

## Testing & Quality Gates

- **Unit & integration tests** – Execute `dotnet test` (or `dotnet test UnicodeSpoofGuard.sln`) to validate detection logic, policy handling, threat-intel gating, and canonicalization.
- **Dataset freshness** – `.github/workflows/confusables-staleness.yml` runs weekly and on PRs to verify the bundled confusables data against Unicode.
- **Performance profiling** – Use `dotnet run --configuration Release --project tools/ProfileStartup/ProfileStartup.csproj` (or the `scripts/profile_startup.py` wrapper) to monitor startup regressions after data or code changes.
- **Operational readiness** – Review updated documentation (`docs/data-updates.md`, `docs/operations.md`, `docs/performance.md`) when introducing new feeds or dataset refreshes.

## OutSystems Surface

| Element | Type | Description |
| --- | --- | --- |
| `IsSafeEmail` | Server Action | Evaluates an email address for Unicode spoofing patterns and returns `AnalysisResult`. |
| `IsSafeDomain` | Server Action | Evaluates domains or hostnames for spoof indicators, returning `AnalysisResult`. |
| `IsSafeUsername` | Server Action | Assesses usernames/identifiers for spoof tactics, returning `AnalysisResult`. |
| `GetCanonicalString` | Server Action | Produces a canonical representation of input text. |
| `AnalyzeTextForSpoofing` | Server Action | Returns the full list of `DetailedFinding` items for a piece of text. |
| `RefreshConfusablesData` | Server Action | Refreshes in-memory confusables mappings from a URL or uploaded file and returns `RefreshConfusablesResult`. |
| `AnalysisResult` | Structure | Summarises spoof analysis outcome (`IsSafe`, `Reason`, `CanonicalValue`, `Findings`). |
| `DetailedFinding` | Structure | Describes individual findings (type, description, position, substring). |
| `AnalysisOptions` | Structure | Per-call overrides (strict mode, locale, policy profile, threat intel toggle). |
| `RefreshConfusablesResult` | Structure | Outcome metadata for a confusables refresh (success flag, message, version, timestamps, entry count). |
